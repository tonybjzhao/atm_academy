- Scenario IDs: `'beginner_crossing_conflict'`, `'false_recovery_tunnel_vision'` — data keys
- Node type IDs: `'missed-conflict'`, `'recovery-interruption'` — internal graph node identifiers
- Category matching: `'ignored'`, `'unattended'`, `'runway'`, `'go-around'` — keyword detection logic

**Rationale:** These strings are part of the simulation/debrief engine logic and should not be exposed to localization, per the requirement "do not add major engines/features."

### 1.3 Fallback/Detail Strings (Dynamically Localized or Simulation-Generated)

The following appear in cascade node detail/description fields:
- `'Conflict cue was not resolved before separation pressure rose.'` → displayed only if no event detail available; otherwise uses event label (which may be translated)
- `'Workload rose as unresolved alerts and commands competed.'` → similar fallback pattern
- `'A conflict was resolved later than the traffic picture required.'` → fallback
- Recovery activity explanations in edge text — dynamically built from typed factors ('alert density', 'close timing', etc.)

**Localization Approach:** These fallback strings are generated at the simulation boundary. The current adapter (`RadarTrainingTextLocalizer`) handles known English phrases and maps them to ARB keys. Unknown phrases fall through unchanged.

**Risk Assessment:** ✅ **Low** — These are predominantly generated by the simulation engine and would require deep refactoring to pre-localize. Current approach (adaptive mapping + fallback) is pragmatic for this iteration.

## 5. Known Limitations & Recommendations

### 5.1 Limitations

1. **Simulation-Generated Text:** Some debrief/insight lines are dynamically generated by the cognitive simulation engine and can only be partially localized via keyword matching. Full localization would require simulation engine refactoring (out of scope per user requirements).

2. **Cascade Edge Explanations:** Explanations like "Evidence suggests X likely contributed to Y through [alert density, close timing, ...]" include dynamically inserted factor text. English phrases are caught by the localizer, but novel generated phrases may appear untranslated.

3. **Fallback Behavior:** When a generated English phrase is not in the localizer's mapping and locale is not 'en', the English phrase is displayed as-is (fail-soft).

### 5.2 Recommendations for Future Work

1. **Phase 2:** Extend `RadarTrainingTextLocalizer` with regex patterns for more dynamic line templates (e.g., "Evidence suggests ... through ...").

2. **Phase 3:** Refactor debrief engine to accept a localization context and produce localized labels at generation time (requires coordination with simulation engine).

3. **Maintenance:** When new debrief insights or cascade nodes are added, remember to:
   - Add English label/description in the generation code
   - Add mapping in `RadarTrainingTextLocalizer` 
   - Add translation keys to `app_*.arb` files
   - Regenerate with `flutter gen-l10n`
